# Gestió — Pantalla d'accés («Capvespre al prat»)

Status: IMPLEMENTED in Gestió (`gestio/public/login-scene.js`, `login.css`, `#login` in `index.html`); lab prototype kept in `gestio/lab/login.html`
Version: 0.4
Phase: visual phase (lab first, integration after approval)

Read with: `DESIGN_VISION.md`, `DESIGN_SYSTEM.md`, `MOTION_SYSTEM.md`.

---

## 1. Purpose

The access screen is the first thing a monitor, monitora or member of the treasury team sees. It
is the one place in Gestió where atmosphere may lead: nobody stays on it, and it can carry the
identity of the group (Parpalló = the hind of the cave, the one on the scarf badge).

It must still be fast, honest about what happens next, and fully accessible.

---

## 2. Authentication reality (non-negotiable)

- Identity is provided by **Cloudflare Access** (ADR-004). Gestió never shows a password field,
  never receives a password and never imitates an identity provider's form.
- One primary action, `Entra amb el teu compte`, starts the Access flow.
- Local development keeps the synthetic identity selector (ADR-002, ADR-007), only when the server
  reports a local environment, with the fictitious-data notice.
- The card works even if the background never loads: the card is the product, the scene is
  decoration.

| State | Trigger | Card content |
|---|---|---|
| Default | No session | Greeting + `Entra amb el teu compte` |
| Redirecting | Button pressed | Button busy (B1), then the «into the light» transition |
| Session expired | Server says the session ended | Warning note `La sessió ha caducat. Torna a entrar.` |
| Access denied | Access identity has no Gestió user | Neutral note `El teu compte no té accés a Gestió. Parla amb coordinació.` |
| Local | `APP_ENV=development` | Synthetic identity selector + `Entra` + fictitious data notice |

## 3. Concept

A small herd of red deer hinds galloping across a meadow at golden hour, drawn as backlit
silhouettes against a low sun. Calm, warm, alive, never cartoonish. The deer are the only thing
that moves with intent; everything else breathes.

Decision (v0.3): no video or photographic assets. The scene is built entirely in code (inline SVG +
WAAPI), so it weighs a few kilobytes, has no licence to track and stays under the CSP.

Scene layers, back to front (generated by `login.js` from a fixed seed, so it is identical on every
visit; palette unchanged: violet → mauve → coral → amber → gold):

| Layer | Content | Ambient motion |
|---|---|---|
| Sky | gradient, faint stars, warm valley glow near the horizon | stars twinkle |
| Clouds | long thin clouds, dark violet tops, undersides lit coral | drift 40–90 px over 90–150 s |
| Sun | low disc, wide glow, soft rays (14 % opacity) | rays sway ±1.6° |
| Birds | four distant birds crossing the sky | fly + flap |
| Far sierra | two rocky ranges (Mondúver-like), hazier with distance; a saddle where the sun sets; crests lit by the low sun | — |
| Valley mist | warm haze between ranges | slow drift |
| Forest ridge | dense Mediterranean woodland: holm oaks, umbrella pines, cypresses (one merged path) | — |
| Meadow | dark rolling ground, a few bushes, lit crest; near herd and hoof dust | — |
| Foreground | grass clumps with seed heads, fennel umbels and light-catching tips | sway |
| Frame | large umbrella pine on the right, rim-lit on the sun side; the herd runs behind its trunk | — |

Light motes drift in the sunlight; static film grain; a scrim behind the card. Trees and clouds are
drawn clockwise so overlapping shapes add up under the nonzero fill rule (no holes).

## 4. The deer

### 4.1 Anatomy (built by `login.js`)

- Local space facing right, hooves on y = 200. Red deer hind proportions: deep chest, slender long
  legs, long neck, large leaf-shaped ears, short tail.
- Parts: torso (with haunch and shoulder mass), tail, neck + head + ears (one group pivoting at the
  base of the neck), four legs.
- Each leg has three rotating joints: shoulder/hip (inside the body), knee/hock, fetlock; segments
  taper (thigh → cannon → pastern) and joints are visible knobs; the hoof is a small wedge.
- Far legs are drawn behind the body in a slightly lighter tone.
- Backlight: a stroked copy of torso, neck and ears is drawn underneath the fill with a warm gradient
  that brightens towards the sun, so only the outer edge glows and joins never show a seam.
- A soft contact shadow on the ground shrinks and fades while the deer is airborne.

### 4.2 Gallop model

Every joint angle is a smooth, periodic function of the stride phase t ∈ [0, 1) (clockwise positive =
hoof swings back). Phase map: 0–.25 hind stance, .2–.45 extension, .45–.72 front stance, .72–1
gathered suspension. Only sines and raised-cosine pulses are used — `pulse(t, c, w)` is
½(1 + cos(π·d/w)) within ±w of c, 0 elsewhere, wrapping around the stride — so no joint has a corner:
they accelerate and settle like muscles. (The v0.2 model used max(0, sin), whose corners showed as
small jerks; the new one is 30–150× smoother by second difference.)

| Part | Function |
|---|---|
| Shoulder | −6 + 36·sin 2π(t − .47) + 4·sin 4π(t − .47) |
| Knee (carpus) | 88·pulse(t, .96, .25) — folds only during the swing |
| Front fetlock | 40·pulse(t, .98, .2) − 13·pulse(t, .58, .14) (gives under load) |
| Hip | 4 + 35·sin 2π(t − .2) + 4·sin 4π(t − .2) |
| Hock | −62·pulse(t, .7, .25) + 9·pulse(t, .1, .12) |
| Hind fetlock | −32·pulse(t, .72, .21) + 10·pulse(t, .1, .13) |
| Body height | −16·pulse(t, .86, .2) − 6·pulse(t, .32, .15) + 3·pulse(t, .58, .12) (compresses on landing) |
| Body surge | 4·sin 2π(t − .3) (speeds up after each push) |
| Body pitch | 3.6·sin 2π(t − .1) + 1·sin 4π(t − .1) |
| Neck | −7·sin 2π(t − .25) |
| Head | 5·sin 2π(t − .25) − 2.6·sin 2π(t − .1) (counter-rotates: the eyes stay almost level) |

- 64 keyframes per joint, played with WAAPI (linear, infinite). Far legs land 7–8 % later
  (transverse gallop footfall order). Each deer starts at a random phase.
- While running the ears pin back (−16°) and the tail lifts (−28°), eased over 600 ms.
- Each crossing runs 6 % faster or slower at random; travel speed scales with it, so the hooves
  stay planted.

### 4.3 Herd and speed

- Three hinds: two near (scales 1.2 and 0.95) running together, one far on the misty ground (0.5).
- Ground speed matches the hooves (≈230 local units per stride), so hooves never slide. The two
  near deer share one speed; the smaller takes quicker strides. The far one is slower on screen.
- They cross from off-screen left to off-screen right, then pause 4.5–8 s before the next crossing.
- Reduced motion: the herd stands still in the meadow; one grazes with the head down.

## 5. Motion timeline

| t | Event |
|---|---|
| 0 ms | Card is interactive immediately (no animation blocks the button) |
| 0–900 ms | Scene fades in |
| 150 ms | Card rises 12 px → 0 with the spring token |
| 900 ms | First crossing starts; hoof dust puffs every half stride |
| on `Entra` | Button busy ≥ 450 ms → «into the light»: the scene scales ×1.25 towards the sun, the card fades and shrinks, the screen settles on `--bg-primary`. Production then goes to Access; on return Inici plays its once-per-session entrance |

Ambient motion (allowed only on this screen): motes, grass, twinkling stars, the sun breathing.
Pointer parallax on fine pointers only: up to 12 px on the nearest layers, smoothed (600 ms).

---

## 6. Accessibility

- `prefers-reduced-motion` (or the lab switch): the herd stands still (one grazing); no motes, grass
  sway, parallax or crossing. The enter transition becomes a 200 ms fade.
- WCAG 2.2.2: visible `Atura l'animació` / `Reprén l'animació` control (bottom right) pauses CSS
  and WAAPI animations.
- Scene `aria-hidden="true"`; the caption is real text. Card: real `<h1>`, primary button first
  in tab order, visible focus. Contrast of the card is checked over the brightest frame (the card
  is near-opaque glass plus a scrim for that reason).

---

## 7. Performance budget

- One inline SVG, no images or media files, no libraries; < 400 nodes including the herd.
- Only `transform` and `opacity` animate; no animated filters. All animations pause when the tab is
  hidden.
- Card first, scene after: the button is usable before the background exists.

---

## 8. Responsive

- Desktop: card on the left third over the scrim; the herd crosses the whole meadow behind it.
- Mobile (< 768 px): card at the bottom as a sheet (thumb reach), the scene fills the top. No
  parallax.

## 11. Implementation in Gestió (v0.4)

- `#login` is a full-screen section before `.app-shell` in `index.html`; it keeps the ids app.js uses
  (`identity`, `loginButton`, `localDataNotice`) and adds `loginTitle`, `loginLead`, `loginNote`,
  `loginLocal`, `loginButtonLabel`, `loginCard`.
- `login-scene.js` is a separate module (app.js never imports it). It builds the scene the first time
  the screen becomes visible, runs only while it is visible (MutationObserver on `body.class` and
  `#login[hidden]`), stops every animation once the session starts, and makes `.app-shell` inert while
  the screen covers it.
- `body.auth-pending` hides both screens until the first session check answers, so a signed-in user
  never sees the scene flash.
- `views/access.js` (created by app.js): the card note mirrors the shell message while signed out (session expired → warning, load
  error → error, 403 → no access). Local: identity selector + `Entra`. Production (dev identities 404):
  `Entra amb el teu compte` reloads, so Cloudflare Access authenticates again.
- After a successful sign-in `views/access.js` dispatches `gestio:login-leave`, waits 900 ms (150 ms with reduced
  motion) for «into the light», then loads the session; the curtain ends on `--bg-primary`.
- The card is always dark (tokens redefined on `#login`); the curtain uses the user's theme.

## 12. v2 — procedural engine (lab: `gestio/lab/v2/`, pending approval)

Motion-design review of v0.4 and what v2 changes:

| v0.4 problem | v2 answer |
|---|---|
| A loop, not a story: the herd always enters already galloping | A **director** runs a story with variation: graze (strolls, turns, look-ups) → one hind hears something, the **alarm spreads** (0.3–0.8 s) → **startle leap** and flight (turning first if facing away) → empty meadow → the herd **returns galloping and brakes** to graze, or sometimes just crosses |
| One gait | **Graze, alert, walk, gallop, turn.** Walk is a four-beat lateral sequence; walk ↔ gallop **blend continuously by speed**; physical acceleration (950 u/s²) and braking (v² = 2·a·d, so the hoof stops on the mark) |
| Hooves could slide when speed changed | Stride phase advances **with distance**, not time (stride 170 u walking, 265 u galloping) |
| Flat ground | Hinds **follow the meadow** and pitch with its slope |
| Head and ears fixed | **Head-carriage controllers** per mode (chewing, look-ups, alert), **spring** ears and tail with random flicks; the tail lifts in alarm |
| Light ignores the deer | The **rim burns on the side that faces the sun**, strengthens near it and **widens when a silhouette crosses the disc**; rays and a lens flare (anamorphic streak + ghosts) **dim when the sun is occluded**; contact shadows fall away from the sun and shrink while airborne |
| Locked camera | Slow **camera drift** (37 s / 16 s / 29 s sines) combined with the pointer, eased every frame |
| Each grass clump sways alone | A **wind field**: a travelling wave plus **gusts that cross the meadow** (470 u/s) |
| Static time | The **sun keeps sinking** while the screen stays open (4 min): dusk deepens, stars brighten, rays fade |
| — | Birds **flap and glide**; out-of-focus **bokeh** in the foreground |

Engine: one `requestAnimationFrame` loop (≈60 SVG attribute writes per frame, 58–60 fps measured in the
lab), stopped whenever the screen is hidden, paused by the WCAG control and by a hidden tab. Reduced
motion renders a still life (herd grazing, one hind looking up, no animation at all).
Lab controls: speed (¼×, 1×, 4×), restart the story, debug overlay (fps, director phase, actors).

## 13. v2 — performance

The expensive part of an animated scene is rarely JavaScript: it is what the browser has to repaint and
blend every frame. v2 is organised around that.

| Cost in the first v2 | Change |
|---|---|
| One full-screen SVG: camera drift, clouds, grass and the sun invalidated large areas every frame | **Two parallax planes** (`#lgFarPlane`, `#lgNearPlane`) painted once and moved with `translate3d` (compositor only) |
| Camera set through an inherited custom property on the stage → style recalculation of hundreds of SVG nodes per frame | The engine writes `transform` on the two planes only |
| Hinds and grass transformed inside the big SVG | **Each hind and each grass clump is a small layer** (`.lg-deer`, `.lg-clump`); moving or bending them repaints nothing — a frame repaints three small silhouettes (their joints) |
| Card `backdrop-filter: blur(28px)` over a moving background | `blur(14px)` with a more opaque card (similar look, a fraction of the GPU cost) |
| Four `mix-blend-mode` layers (grain, flare, bokeh, rays) | Plain alpha; grain opacity halved |
| Rays rotating, sun breathing, mist and every cloud drifting inside the SVG | Rays and mist static; the whole cloud layer drifts on the compositor; only a third of the stars twinkle |
| Sunset updating the sky every frame | Updated only when the sun moves ≥ 0.35 units |
| Off-stage hinds still computed; rim styles rewritten every frame | Skipped / written only when the value changes |
| Dust as SVG nodes | HTML spans animated by the compositor |

Measured in the lab while the herd gallops (main thread per frame, median / p95): v0.4 **3.4 / 4.7 ms**,
v2 **2.2 / 3.3 ms**, at a steady 60 fps, despite v2 doing much more. Raster/GPU savings (no full-screen
repaint, smaller blur, no blend modes) are larger but are not visible in that number.

**Adaptive quality**: if frames stay slower than 40 fps for two seconds, the engine switches to *lite*
(no wind, flare, bokeh, motes or dust; the far hind posed every other frame). The loop stops when the
screen is hidden, the tab is in the background or motion is paused.
